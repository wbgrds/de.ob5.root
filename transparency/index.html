Transparency

Warum machen wir es so? Alles offen.

Transparenz heißt: Wir zeigen dir, was wir benutzen. Nicht Marketing-Versprechen – faktische Tech-Stack-Offenlegung. Hier sind die Tools, die WEBGUARDS & OB5 antreiben. Warum? Was können sie? Was nicht?

Unser Tech-Stack

SIPGATE

Telefonie & Dashboard

Was: Cloud-basierte VoIP-Plattform für Telefonie, SMS, Fax – mit REST-API und Web-Dashboard.

Warum:

  • Stabil, zuverlässig, Deutsche Infrastruktur
  • API-First – Integration in eigene Systeme möglich
  • Transparente Preisgestaltung (pro Minute/SMS)
  • Keine Vendor Lock-in – Port-away jederzeit

Wie integriert: OAuth2-Dashboard für Kal-MCP (KI-Assistenten), REST-API für Custom-Apps, Telefonie-Integration für Kundenwebseiten.

Nachteile: Nicht billig für große Mengen. UI teilweise veraltet. Aber: Stabilität > UX-Glanz.

3CX + easybell

Call Center & VoIP

Was: 3CX ist eine On-Premise/Cloud-basierte Telefonanlage. easybell stellt SIP-Trunks (Telefonienleitungen) bereit.

Warum:

  • 3CX: Open Standard (SIP) – nicht proprietär
  • easybell: Deutsche Carrier, zuverlässig, günstig
  • Zusammen: Komplette Kontrolle über Telefonie – Call Recording, IVR, Queues, Reporting
  • Skalierbar – von 1 bis 1000 Agenten

Wie integriert: Call-Center für WEBGUARDS-Kundensupport, Recording für Compliance, Webhooks für KI-basierte Call-Routing-Automatisierung.

Nachteile: Setup komplex. easybell-Support mittelmäßig. Aber: Bei richtig konfiguriert, läuft es stabil.

Claude (Anthropic)

KI & Automation

Was: LLM von Anthropic – für Textanalyse, Code-Generierung, Kundenkommunikation, Automatisierung.

Warum:

  • Beste Qualität (Stand 2026) – Reasoning, Context-Window, Zuverlässigkeit
  • API mit Tool-Use – Anbindung an externe Systeme (GitHub, Gmail, etc.)
  • Transparenz bei Safety – Anthropic dokumentiert Ansätze offen
  • Flexibles Preismodell – Pay-per-Token

Wie integriert: Kal-MCP (KI-Assistenten für Kundensupport), Code-Review & Refactoring, Dokumentation automatisieren, Kundenwebseiten mit KI-Features ausstatten.

Nachteile: API-Kosten addieren sich. Rate-Limits bei hohem Volumen. Aber: Kosten-Nutzen ist fair.

GitHub

Version Control & Collaboration

Was: Git-Hosting, Code-Repository-Management, Pull Requests, Issue-Tracking, GitHub Actions (CI/CD).

Warum:

  • De-facto Standard – Industrie-Standard für Open Source & Teams
  • Volle Git-Kontrolle – nicht proprietär, echtes Git darunter
  • GitHub Actions – kostenlose CI/CD für kleine Projekte
  • Transparenz: Public Repos sind wirklich öffentlich. Code ist lesbar.

Wie integriert: Alle WEBGUARDS- & OB5-Repos (wbgrds/*, WEBGUARDS-DE/*), Versionskontrolle, Deployment-Automation, Code-Review für Kunden, Issue-Tracking für Projekte.

Nachteile: Abhängig von Microsoft. Private Repos kosten. Aber: Preis fair, Abhängigkeit akzeptabel für diese Zentralität.

GitHub Pages

Static Hosting

Was: Kostenloses Hosting für statische Websites – HTML/CSS/JS direkt aus GitHub Repos deployen.

Warum:

  • Kostenlos – keine Hosting-Rechnung für statische Sites
  • Deployed mit Git Push – Workflow: Code → git push → Live
  • Custom Domains – CNAME-Support für deine Domains
  • Version Control = Deployment History – Jeder Git-Commit ist eine Version

Wie integriert: OB5 (ob5.de, ob5.dev), WEBGUARDS-Website, Kundenlandingpages, Dokumentations-Sites, Portfolio.

Nachteile: Nur statisch – kein Backend, keine Datenbank. Für dynamische Apps brauchst du einen echten Server. Aber: Pages → Server ist leichte Migration.

Domains (Registrar: Netcup)

DNS & Domain Management

Was: Registrar & DNS-Hosting – Domains kaufen, verwalten, DNS-Records konfigurieren.

Warum wir Netcup:

  • Deutsche Infrastruktur – DSGVO-konform
  • Transparente Preise – keine versteckten Gebühren
  • API-Zugang – DNS-Records automatisiert ändern (Let's Encrypt, Certification, etc.)
  • Customer Support – Deutsch, erreichbar, kompetent

Wie integriert: ob5.de, ob5.dev, adobe5.de, weitere Kundendomains. DNS-Management für Email, SSL-Zertifikate, CNAME für GitHub Pages.

Nachteile: Kleine Registrar – Support nicht 24/7. Aber: Zuverlässig genug, für deutsche Tech-Teams ideal.

Server (Infrastructure)

Cloud Hosting & Computing

Was: VPS/Cloud-Server für dynamische Anwendungen, Datenbanken, Hintergrund-Prozesse, APIs.

Optionen die wir nutzen:

  • Hetzner Cloud: Deutsche Cloud, günstig, zuverlässig – für 90% unserer Backend-Needs
  • Linode (Akamai): Für hochperformante Anwendungen, besserer Support
  • AWS (sparsam): Für spezifische Services (S3, Lambda) – nicht als Main Host

Wie integriert: Kal-MCP Backend, 3CX-Installation, Custom APIs, Datenbankserver (PostgreSQL, Redis), Cronjobs, Webhooks von SIPGATE/3CX.

Nachteile: Selbst verwaltet – du brauchst DevOps-Skill. Hetzner ist kleiner, weniger Features als AWS. Aber: Kontrolle, Zuverlässigkeit, deutsches Rechenzentrum > Enterprise Bloat.

Wie sie zusammenhängen

Infrastruktur & Datenfluss

Domains (Netcup) → DNS → GitHub Pages (Frontend) oder Server (Backend)

Frontend: Kundenwebseiten auf GitHub Pages (ob5.de, adobe5.de, etc.)
Backend: Server (Hetzner/Linode) für APIs, Datenbanken, dynamische Inhalte
Code: GitHub – Versionskontrolle, Pull Requests, Deployment-Trigger

Telefonie-Flow

Kunde ruft an → easybell (SIP-Trunk) → 3CX (Call Routing/IVR) → Server (Webhook empfangen) → Claude API (Anfrage analysieren) → Automatische Antwort oder SIPGATE (SMS/Notify)

Automation & Deployment

GitHub (Code Push) → GitHub Actions (CI/CD) → Server (Deploy) oder GitHub Pages (Auto-Deploy)
