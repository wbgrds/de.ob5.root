Transparency

Warum machen wir es so? Alles offen.

Transparenz bedeutet: Wir zeigen dir, was wir wirklich benutzen. Nicht Best-Practice-Theorie – sondern unser echter Tech-Stack. Warum jedes Tool? Was kostet es? Können wir weg?

Unser Tech-Stack

SIPGATE

Firmenhotline & VoIP

Was: VoIP-Carrier für Telefonie – Cloud-basiert mit SIM-Karte und Nummernblöcken.

Warum wir das nutzen:

  • Firmenhotline für Partnerfirmen (min. 2 Nutzer im Paket)
  • IVR zum Filtern von Spam- und automatisierten Anrufen
  • Importierte Nummernblöcke kostenlos, nur neue Nummern kosten extra
  • SIM-Karte inkludiert

Wie integriert: Jede Partnerfirma nutzt einen Nutzer im gemeinsamen Paket. Alle haben Zugang zu IVR und Nummernblöcken.

Kosten: ~26€/Monat (Paket ab 2 Nutzern)

3CX + easybell

Team-Kommunikation

Was: 3CX = Cloud PBX für Team (VoIP, Chat, Meetings). easybell = SIP-Trunk für externe Festnetznummer.

Warum wir das nutzen:

  • Internes Team telefoniert, chattet, trifft sich – alles in 3CX
  • 3CX Cloud kostenlos bis 10 Nutzer
  • Jeder Nutzer hat eigene Durchwahl
  • easybell SIP-Trunk verbindet externe Anrufe
  • Open Standard (SIP) – nicht proprietär

Kosten: ~1,99€/Monat (easybell Festnetznummer). 3CX kostenlos (10er-Plan).

Claude Pro

Internes KI-Tooling

Was: KI-Assistant für Coding, Dokumentation, Projektmanagement, Organisation.

Warum wir das nutzen:

  • Tägliches Werkzeug für Team (Coding, Docs, Planung)
  • Beste Qualität (Stand 2026)
  • Flat-Rate = Kosten bleiben überschaubar (nicht API-basiert)
  • Nutzen nur Pro-Plan, nicht API (um Kosten zu kalkulieren)

Wie integriert: Team nutzt Claude Chat direkt. Nicht in Kundenprodukte eingebaut (würde API kosten).

Kosten: 18€/Monat netto (Claude Pro Plan)

GitHub

Knowledge Base + Deployment

Was: Git-Hosting mit 40 Private Repos – als Knowledge Base und Deployment-Source.

Warum wir das nutzen:

  • 40 Private Repos als Knowledge Base (CLAUDE.md mit Prompts, Tech Stacks)
  • GitHub API – jeder Nutzer Token → Claude arbeitet direkt mit Repos
  • Deployment nur via Claude/KI (kein Nutzer-Wissen nötig)
  • Public Repos für statische Webseiten (→ GitHub Pages)
  • Kundendaten NICHT in GitHub (laufen auf Homeserver)

Wie integriert: Claude liest Private Repos als Kontext, pusht Code-Änderungen automatisch, triggert Deployments.

Kosten: 0€ (Private Repos kostenlos)

GitHub Pages

Website Hosting

Was: Kostenloses Hosting für statische Webseiten – direkt aus GitHub deployen.

Warum wir das nutzen:

  • Alle eigenen Webseiten laufen darauf (webguards.de, ob5.de, etc.)
  • Auch einige Kundenwebseiten
  • Content-Management via Claude: Smartphone-Befehl → Änderung → Live
  • Kein Login nötig, keine Umständlichkeit – nur Chat
  • Kostenlos

Wie integriert: Claude editiert Seiten (Markdown/HTML), pushed zu GitHub, Live-Deploy automatisch.

Kosten: 0€

Domains (Hetzner)

Domain & DNS Management

Was: Domain-Registrierung und DNS-Hosting.

Warum wir zu Hetzner gewechselt haben:

  • Ursprünglich: Kontent.com → Google Domains → Squarespace
  • Squarespace übernahm Google Domains, Service ließ nach
  • Jetzt: Hetzner (DNS kostenlos, nur Domain-Jahresgebühr)
  • Günstiger als Squarespace (~12€/Jahr/Domain)

Aktuell: 6 Domains insgesamt. 1 bei Hetzner registriert, 5 noch bei Squarespace. DNS aller 6 läuft über Hetzner. Migration: Oktober 2024 erste, dann alle bis 2027.

Kosten: ~1€/Monat (amortisiert über alle Domains)

Server (ionos + Homeserver)

Homeserver + Cloud

Was: Eigene Homeserver (4x Altgeräte) an 2 Standorten + ionos Mini VPS.

Warum wir das so machen:

  • Homeserver: Kundendaten liegen bei uns (nicht external), Glasfaser-Anbindung
  • 2 Standorte: Geografische Redundanz (Ausfallschutz)
  • Getrennt nach: Webseiten | Prototypen | Tools
  • Kunden: Jeder kriegt eigenen Server (kein Cascade-Ausfall)
  • ionos Mini VPS: Für zusätzliche Services (3€/Monat)

Kosten: Glasfaser 35€/Monat + ionos 3€/Monat = ~38€/Monat. Hardware amortisiert (Altgeräte), Strom minimal (~50 Watt).

Keine Vendor Lock-in – Port-away jederzeit

Unser Tech-Stack ist bewusst so gewählt, dass du jederzeit weg kannst. Keine Abhängigkeit. Deine Daten gehören dir.

SIPGATE → Alternative

Lock-in Faktor: Mittel (Telefonnummern portierbar)

Exit Strategy:

  • Nummernportierung zu anderem Carrier (3–4 Wochen)
  • Historische Daten: CSV-Export möglich
  • API-Integration: REST-basiert, nicht proprietär
  • Zu wem? Vonage, Twilio, Asterisk (Self-hosted)

3CX → Alternative

Lock-in Faktor: Niedrig (Open Standard SIP)

Exit Strategy:

  • 3CX ist SIP-basiert – alle Daten sind Standard-Format
  • Export: Config, Call Logs, Voicemails (alle Standard)
  • Alternative PBX kann 1:1 konfiguriert werden
  • Zu wem? Asterisk, Freeswitch, andere SIP-PBX

Claude Pro → Alternative

Lock-in Faktor: Niedrig (Prompts sind übertragbar)

Exit Strategy:

  • Claude Pro ist ein Service, keine Code-Integration
  • Prompts und Arbeitsprozesse sind auf andere LLMs übertragbar
  • Keine proprietären Abhängigkeiten im Code
  • Zu wem? ChatGPT, Google Gemini, Open Source LLMs (Llama, Mistral)

GitHub → Alternative

Lock-in Faktor: Niedrig (echtes Git)

Exit Strategy:

  • Git ist Standard – `git clone`, lokale Kopie, migrieren
  • Issues/PRs sind Git-Standard (können exportiert werden)
  • GitHub Actions → GitLab CI/CD oder selbst hosten
  • Zu wem? GitLab, Gitea (Self-hosted), Codeberg

GitHub Pages → Alternative

Lock-in Faktor: Sehr niedrig (statische HTML)

Exit Strategy:

  • Pages sind reines HTML/CSS/JS – keine Abhängigkeit
  • Upload zu beliebigem anderen Host (Hetzner, Vercel, Netlify)
  • Keine Generator-Lock-in (falls Jekyll): Standard-Dateien
  • Zu wem? Netlify, Vercel, Hetzner, selbst gehosteter Server

Domains (Hetzner) → Alternative

Lock-in Faktor: Sehr niedrig (Standard-DNS)

Exit Strategy:

  • Nummernportierungscode (AuthInfo) anfordern
  • DNS ist Standard – einfach zu anderem Registrar übertragen
  • Keine proprietären Zone-Files
  • Zu wem? GoDaddy, Strato, OVH, Squarespace, beliebiger anderer Registrar

Server (ionos + Homeserver) → Alternative

Lock-in Faktor: Niedrig (Linux-Standard)

Exit Strategy:

  • Alle Daten auf Standard Linux – exportierbar
  • Datenbank (PostgreSQL): Standard-Export
  • Docker/Snapshots: zu anderem Host migrierbar
  • Zu wem? Hetzner, Linode, AWS, DigitalOcean, Scaleway, eigenes Datacenter

Unser Prinzip: Standard over Proprietary

Jedes Tool, das wir wählen, erfüllt eine Anforderung:

  • Open Standards: Git, SIP, REST-API, DNS
  • Portable Daten: CSV, JSON, SQL-Dumps, oder reines HTML/CSS
  • Export-Funktionen: Nichts versteckt, alles zugänglich
  • Konkurrenz existiert: Wenn wir weg wollen, gibt es einen Plan B

Das bedeutet: Du kannst uns verlassen. Und das ist absichtlich. Vertrauen sollte nicht auf Lock-in basieren – sondern auf Qualität.
